## ★ 01. name card（いぬにゃん／たけしま れみ）

- **URL：** https://ivory634684.studio.site/
- **制作：** いぬにゃん本人（STUDIO製）
- **位置づけ：** **ゆうぎりさんに「名刺ハブサイトとはこういうもの」として提示した実例。**
  つまりゆうぎりさんの頭にある完成イメージの基準点。最重要リファレンス。
- **該当条件：** **A（全面ゴシック）**／部分的に B

### 参考にする点

**① 2名義の同居を、構造で解決している** 🔑
```
Takeshima  れみ          ← 本名（remishima）
      たけしま れみ
        ／               ← 大きなスラッシュで対等に区切る
      INUNYAN
       いぬにゃん         ← 活動名
```
- どちらかを主にせず、**「／」で対等に並置**。上下でも入れ子でもない。
- さらに **実績1件ごとに `（いぬにゃん）` `（remishima）` と署名**して、
  どちらの人格の仕事かを明示している。
- → **これは Yoriyoi の「ゆうぎり ↔ 本名CEO」問題そのものの解**。
  HCD Phase① で「取り違えのリスク」として挙げた課題に、実装解が既にある。

**② ゴシック＋広い字間で「硬質だが親しみ」を両立**
- 見出しは極太ゴシック。ただし**字間を大きく開ける**ことで圧を抜いている。
- ラテン文字の小見出し（`ABOUT` `INUNYAN`）はさらに字間を開けて記号的に扱う。
- → 新方針「全面ゴシック・ウェイトで階層」の**成功例**。明朝なしでも品がある。

**③ 直線的なレイアウトに、手書き曲線を1点だけ落とす**
- ページ全体は硬質なグリッド。そこに**サイン（筆記体ロゴ）の曲線が1つだけ**。
- → まさに **「AIは直線、人は曲線」** の構図。曲線は量ではなく**配置の勝負**という示唆。

**④ リンクに番号と説明文をつけている**
- `01 PORTFOLIO` `02 CHINJU` … `07 LLM社会シミュレーション` と**連番**。
- 各項目に2〜3行の説明。「何が見られるか」が事前に分かる。
- → ブランド文書 §16「リンク先の内容が予測できる」を満たしている。

### 合わない点（そのまま真似すると危ない）

- **モノクロ基調**。Yoriyoi は朱赤・山吹・温かいオフホワイトが資産なので、色は引き継げない。
- **縦に長い**（約6,700px）。個人ポートフォリオとしては良いが、
  名刺を受け取った初対面の人が数十秒で見る用途には長い。
- 顔写真・アバターがない（サインロゴで代替）。ゆうぎりさんはビジュアル資産が強いので事情が違う。

### Yoriyoi への翻訳

| 借りるもの | どう変えるか |
|---|---|
| 「／」による2名義の対等な並置 | **そのまま採用候補。** ゆうぎり／本名CEO に適用できる |
| 実績への名義タグ | リンクに `（ゆうぎり）` `（Yoriyoi）` を付けて出自を明示 |
| 極太ゴシック＋広い字間 | 採用。ただし Yoriyoi は色があるので、字間はやや控えめに |
| 曲線を1点だけ置く | **量を増やさない指針として採用。** 縒り線は区切りに1〜2箇所まで |
| 番号＋説明文つきリンク | 検討。ただしFV収納との両立に注意（下記） |

### ⚠️ 現行WFとの相違（要判断）

| | 現行の card-hub WF | この参考サイト |
|---|---|---|
| リンク | ラベルのみ・**FV内に収める** | 番号＋説明文・**縦長スクロール** |
| 名義 | URLで出し分け（`/yugiri`・`/ceo`） | **1ページに両方を並置** |
| 色 | 朱赤・山吹・地紋あり | モノクロ |

→ 特に**「2名義を分けるか、1ページに並べるか」は設計の分岐点**。
ゆうぎりさんがこのサイトを見て「これ」と言った以上、
**並置案（1ページ）を第2案として検討する価値がある。**
HCD Phase② の要検証項目「ゆうぎり↔本名の切替は混乱を生まないか」に直結。

# バッチ①：AI/DX・組織/事業支援系（チャット調査 2026-07-26）

## 02. Muture　🌟曲線思想
- **URL：** https://muture.jp/ ／ [制作事例(Goodpatch)](https://goodpatch.com/work/muture)
- **該当条件：** B / C / D
- **参考にする点：** 個人を表す形同士を有機的な線でつなぎ「共創」をブランド構造そのものにしている。支援先の**自走＝「伴走の終了」を価値として扱う**姿勢がYoriyoiと極めて近い。
- **合わない点：** 多色グラデや不定形オブジェクトまで踏襲すると、AI社会実装企業でなく**アート/クリエイティブファーム**に見える。
- **Yoriyoiへの翻訳：** 人・専門性を表す2〜4本の曲線を交差させ、中心から「成果」の直線が伸びる構造。終点で曲線がクライアント側へ移り自走を表現。背景=生成り／線=チャコール／接点だけ朱赤・山吹。

## 03. MIMIGURI　🌟複数事業構造
- **URL：** https://mimiguri.co.jp/
- **該当条件：** A / C / D
- **参考にする点：** 「経営モデル→コンサル→学習PF→実績」の展開順。**理念と具体サービスの間に"独自モデル"を置く**中間層。多角化/事業開発/組織/文化/人材の複数領域を同一ブランド下で整理。
- **合わない点：** 「土壌を耕す」等の自然比喩・研究機関的な情報量をそのまま使うと、Yoriyoiの「先に成果を出す」実務性が弱まる。
- **Yoriyoiへの翻訳：** FV直下に「Yoriyoiの伴走モデル」を置き、そこから5事業を展開。枝分かれでなく**一本の糸が役割を変えながら各事業を通過**する構造。

## 04. BIOTOPE
- **URL：** https://biotope.co.jp/
- **該当条件：** C
- **参考にする点：** 「何者か→提供価値→個別サービス」と理念から実務へ降りる順序。性質の異なるサービスを同じ粒度で並置。
- **合わない点：** 「希望の物語を巡らせる」等の表現・3D/WebGL・緑の世界観は**ポエム/自然系と誤認**されやすい。
- **Yoriyoiへの翻訳：** 理念を語る前に「現場を楽にする→使い方を渡す→自分たちで回せる」の道筋を先に提示。その後に思想を説明。

## 05. KESIKI　🌟タイポグラフィ
- **URL：** https://kesiki.jp/ ／ [紹介(WebDesignClip)](https://webdesignclip.com/kesiki-jp/)
- **該当条件：** A / D
- **参考にする点：** 白黒中心に**ウェイト・サイズ・行間・余白だけで編集的な強弱**をつくる。「やさしさ」を丸文字/パステルでなく**大きなタイポと静かな余白で大人っぽく**表現。
- **合わない点：** 抽象メッセージを大きく扱うため初見で支援内容が分かりにくい。真っ白のままだとYoriyoiには硬い。
- **Yoriyoiへの翻訳：** KESIKIのタイポ設計を**温かいオフホワイト＋チャコール**に移植。見出し=太めゴシック／本文=標準ウェイト。曲線は文字背後でなくセクション間の導線に。

## 06. Kakeai
- **URL：** https://kakeai.co.jp/
- **該当条件：** B / C
- **参考にする点：** 中心価値の周囲にツール/カスタマイズ/研修/コンサルを配置し「サービスの集合体」を一つの解として提示。利用シーンで整理。
- **合わない点：** 軌道状の円形表現＋多色グラデは**宇宙/SaaS/テック寄り**。「今すぐDL」型導線は穏やかな人格と不一致。
- **Yoriyoiへの翻訳：** 5事業を閉じた円でなく**一本の糸の途中の役割**として配置。VENは未完成が分かる**点線/開いたループ**で示す。

## 07. Link AI　🌟情報設計

# 🧭 バッチ①からの設計方針（統合）

調査から見えた共通パターンを、Yoriyoiの設計指針に落とす。

### ① 理念とサービスの間に「独自の構造」を置く
優れたサイトは理念からいきなりサービス一覧へ飛ばない：
**理念 → 会社を一文で定義 → 独自モデル・進め方 → サービス → 実績**。
Yoriyoiの中間層は明確に **「成果 → 教育 → 自走」**。これがサイト全体の背骨。
（参考：MIMIGURI / Helpfeel / Link AI / The Ready）

### ② 曲線は「装飾」でなく「関係と変化の説明」に使う
全面に敷くだけでは「やわらかい会社」で終わる。曲線に意味を持たせる：
- **交差＝出会い**（専門家が一時的にチームになる）
- **結び目＝成果**
- **分岐＝事業**
- **離れる動き＝自走**（Yoriyoiの糸が離れ、クライアントだけで続く）

（最も近い参考：Muture）

### ③ 「やさしさ」は丸文字/パステルでなく、余白と説明順序でつくる
ゴシック＋十分な文字サイズ＋短い段落＋広い余白で圧を下げる。
- 背景：温かい生成り／本文：濃いめチャコール
- **朱赤＝人の働き・対話・参加／山吹＝成果・発見・理解**（色に役割を固定）
- 見出し 600〜700／本文 400（細すぎない）
- CTA：「相談してみる」「一緒に整理する」など急かさない

### 現時点の組み合わせ方針
> **骨格＝Link AI ／ 視覚言語＝Muture ／ 文字と余白＝KESIKI ／ 複数事業の整理＝MIMIGURI**

これが現時点で最もYoriyoiらしい方向。次はこの4軸を、まずコーポレートWF（`wireframes/corporate.html`）へ落とす。

### 12. 株式会社才流（サイル）
- **URL：** https://sairu.co.jp/ ／ **該当：** C / D
- **参考点：** 何をする会社かをトップで早く理解させる情報量の置き方。事例・メソッド・知見を分け、抽象論と実務の距離を保つ。

### 13. 株式会社Cone
- **URL：** https://coneinc.jp/ ／ **該当：** C
- **参考点：** サービスを「認知→リード獲得→育成→商談・受注」と**商流に沿って並べる**。思想がそのまま情報設計になり理念が浮かない。

- **翻訳：** 3段階を「現場が楽になる順」で並べる。5事業＋将来構想は上流→下流の一気通貫構造が相性良い。

### 14. 株式会社ベイジ　🌟ゴシック実務
- **URL：** https://baigie.me/ ／ **該当：** A / C
- **参考点：** 全面ゴシック寄りで**余白とウェイト差だけで階層**をつくる。複雑なB2B情報を装飾に逃げず整理。
- **合わない点：** ストイックで「人が編まれている」やわらかさは薄い。そのままだと冷たく見える。
- **翻訳：** 書体はゴシック1本で統一しつつ、線の太さ・余白・角丸・段組みで**やわらかさを足す**。実務感=ベイジ／空気感=Yoriyoi独自。

### 15. 富士ソフト 導入事例
- **URL：** https://www.fsi.co.jp/cases/ ／ **該当：** C
- **参考点：** 事例を業種/キーワードで探せる整理。課題・解決・効果が意思決定材料になる見せ方。
- **合わない点：** 詩情・人格は出ない。実務寄りすぎて「縒る・寄り合い」の世界観は感じにくい。
- **翻訳：** 事例を用途別でなく**変化の段階別**に束ねる。事例カードに成果＋"現場が楽になったこと"を短く添える。

### 16. メンバーズ
- **URL：** https://www.members.co.jp/results ／ **該当：** C
- **参考点：** 事例を前面に出し、抽象説明より先に「何をやってくれる会社か」を理解させる。事業の広がりを実績で信頼に変換。
- **合わない点：** 企業サイトの定型感が強い。「救う／伴走を終える」の物語は薄まる。
- **翻訳：** 「できること」を並べる前に「どの順番で楽にするか」を示す。事例は業種別でなく**困りごとの種類別**に。

### 17. 三菱商事
- **URL：** https://www.mitsubishicorp.com/jp/ja/ ／ **該当：** A / C
- **参考点：** ゴシック主体でも企業の格を保つ見せ方。複数事業を雑多に見せず束ねる構造。
- **合わない点：** 規模感が大きすぎ、柔らかい親密さは出しにくい。距離が遠い。
- **翻訳：** 事業の多さを「大きさ」でなく**「寄り合いの多様さ」**として。信頼感の出し方だけ借り、温度は近く。

### 18. GOOD PLACE　（唯一のB＝曲線系）
- **URL：** https://www.goodplace.co.jp/ ／ **該当：** B / C
- **参考点：** 空間・人・実務のつながりの見せ方。「線でつなぐ」発想をサービス導線・図解に転用しやすい。
- **合わない点：** 建築・空間寄りの文脈で、AI社会実装とはそのままズレる。
- **翻訳：** 線が近づき・交差し・また離れる表現を**関係図/プロセス図**に置換。装飾でなく「関係性の見える化」として。
