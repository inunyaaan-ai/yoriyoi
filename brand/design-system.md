## 1. Brand Overview

> 🔴 **要改訂**：以下の Brand Definition は方向転換前の記述です。現在の定義は [message.md](message.md) を参照。
> 現行：「株式会社Yoriyoiは、人・知識・経験・テクノロジーをつなぎ、企業・地域・教育機関・クリエイターと共に、これまでになかった選択肢を生み出します。」

### Brand Name

**Yoriyoi／よりよい**

### Brand Definition

Yoriyoiは、AIを活用して、人材とプロジェクトのよりよい出会いを支援するブランドです。

人を一方的な基準で評価し、ひとつの正解へ当てはめるのではなく、一人ひとりが持つ経験、志向、価値観、働き方と、プロジェクトが必要とする役割、環境、目的を丁寧に整理します。

AIが答えを決めるのではなく、双方が互いを理解し、納得して選ぶための材料を提供します。

---

## 2. Brand Purpose

### Purpose

**一人ひとりが、自分にとってのよりよい選択をできる社会をつくる。**

Yoriyoiが目指すのは、誰かが定めた「正しいキャリア」や「理想的な働き方」へ人を当てはめることではありません。

人とプロジェクトの間にある情報や可能性を整理し、それぞれが自分らしい選択をできる状態を支援します。

---

## 3. Brand Promise

**人とプロジェクトの、よりよい出会いをつくる。**

Yoriyoiは、人材とプロジェクトの違いを消すのではなく、それぞれの特性が活きる関係を見つけます。

---

## 4. Brand Concept

### Core Concept

**違いを残したまま、可能性を縒り合わせる。**

異なる人、経験、価値観、働き方、目的、環境が、それぞれの個性を失うことなく緩やかに関係をつくる。

Yoriyoiは、人とプロジェクトの間にある接点を見つけ、双方がよりよい関係を築くためのきっかけを設計します。

### Supporting Statement

**それぞれの可能性を、よりよい出会いへ。**

---

## 5. Brand Structure

Yoriyoiのブランドは、以下の3層で設計します。

### WHY：なぜ存在するのか

一人ひとりが、自分にとってのよりよい選択をできるようにするため。

### HOW：どのように実現するのか

人、経験、価値観、働き方、プロジェクトの目的や環境を丁寧に整理し、異なる可能性を縒り合わせる。

### WHAT：何を提供するのか

AIを活用し、人材とプロジェクトの相性や可能性を可視化し、双方が納得して選べるマッチングを支援する。

## 6. Logo Concept

### Logo Story

Yoriyoiのロゴ上部には、朱赤と山吹色の紐が緩やかに縒り合うモチーフが描かれています。

この紐は、異なる人、経験、価値観、感情、目的、プロジェクトが、それぞれの違いを残したまま関わり合う姿を表しています。

紐は一直線ではありません。

近づいたり、離れたり、交差したりしながら、ひとつの流れをつくっています。

それは、人と人との関係だけでなく、自分自身との関係にも似ています。迷ったり、立ち止まったり、ときにはほどけたりしながら、自分なりの働き方や生き方を少しずつ見つけていく。

Yoriyoiが大切にするのは、完成された正解ではなく、その過程です。

### Name Meanings

「Yoriyoi」という名称には、以下の意味を重ねています。

- より良い
- 複数の糸を撚り合わせる「縒る」
- 人が集まり言葉を交わす「寄り合い」
- 主宰者や起点を示す「Y」

### Logo Element Meanings

| Element | Meaning |
|---|---|
| 縒り合う紐 | 人、経験、価値観、目的、対話のつながり |
| 朱赤 | 人のぬくもり、意志、生命感 |
| 山吹色 | 希望、気づき、日常に生まれる小さな光 |
| 二色が交互に続く構造 | 違いを消さず、対等に関係をつくること |
| 緩やかな曲線 | 揺らぎ、余白、変化を許容する姿勢 |
| 始点と終点 | 閉じた関係ではなく、外へ続く可能性 |
| 細く伸びやかな文字 | 押しつけない伴走、静かな知性 |

### Logo Statement

**それぞれの色のまま、緩やかに縒り合う。**

## 8. Brand Personality

Yoriyoiの人格は、以下の3つを掛け合わせた存在です。

- 親しい編集者
- 安心して話せる場のホスト
- 少し先を歩く伴走者

### Personality Attributes

- やさしいが、幼くない
- 知的だが、難解ではない
- 親しみがあるが、馴れ馴れしすぎない
- 前向きだが、ポジティブを強要しない
- 答えを決めるのではなく、一緒に考える
- 人を評価するより、可能性を整理する
- 静かなユーモアと人間らしさがある
- 完璧でない状態や迷いを尊重する

---

## 9. Experience Principles

### 9.1 押しつけず、選べる

ひとつの正解だけを提示せず、複数の可能性と、その理由を見せる。

### 9.2 評価せず、可能性を見つける

人を点数や順位だけで扱わず、その人の特性が活きる環境や役割を示す。

### 9.3 ブラックボックスにしない

「なぜこの組み合わせなのか」を、専門知識がなくても理解できる言葉で説明する。

### 9.4 人が最後に決める

AIの推薦を決定事項にせず、本人とプロジェクト双方の意思、対話、確認を尊重する。

### 9.5 違いをつなぐ

人材とプロジェクトの違いをなくすのではなく、補い合える関係や新しい可能性を探す。

### 9.6 急かさない

「今すぐ応募」「すぐに決める」だけでなく、「詳しく知る」「保存する」「相談する」「今は決めない」という選択肢を用意する。

## 10. Tone of Voice

### Voice Principles

- 簡潔で分かりやすい
- 穏やかで誠実
- 専門用語を必要以上に使わない
- 人をラベルで固定しない
- AIを万能な存在として扱わない
- 行動を急かさない
- 本人の判断と意思を尊重する

### Preferred Expressions

- 一緒に考える
- 整理する
- 可視化する
- 選択を支える
- 可能性を見つける
- 納得して選ぶ
- よりよい出会い
- 活かせる環境
- 相性を知る
- 次に確認したいこと

### Avoided Expressions

- AIがあなたの未来を決める
- 絶対に成功する
- 完璧なマッチング
- あなたに最適な仕事はこれです
- 市場価値を判定する
- 不適合
- 劣っている
- 今すぐ変わろう
- 成長しなければならない
- AIに任せれば大丈夫

## 12. Color System

近黒の地に、朱赤から山吹へ変化する光を重ねます。朱赤は「人の働き」、山吹は「成果」を表し、その間のグラデーションを「働きが成果へ変わる過程」として扱います。

### Palette (Confirmed HEX)

| Token | Name | HEX | 役割 |
|---|---|---|---|
| `--color-red` | Human Red | `#E4572E` | 人の働き、グラデーションの起点 |
| `--color-red-deep` | Human Red / Deep | `#C8452A` | 番号・ドット、低発光時の補助 |
| `--color-yellow` | Outcome Gold | `#E4A02B` | 成果、グラデーションの終点 |
| `--color-bg` | Ground | `#120F0A` | ページ背景 |
| `--color-bg-raised` | Ground / Raised | `#17150F` | ナビ、沈んだ面 |
| `--color-surface` | Glass | `rgba(24,20,16,.30)` | カード、セクション |
| `--color-surface-2` | Glass / Hover | `rgba(255,255,255,.07)` | hover 面 |
| `--color-border` | Glass Edge | `rgba(255,255,255,.13)` | 境界線 |
| `--color-text` | Warm White | `#F7F1E7` | 見出し・本文 |
| `--color-text-soft` | Warm Gray | `#BDB4A6` | 補助文、キャプション |
| `--color-white` | White | `#FFFFFF` | 最前面の文字 |

### Gradient（限定使用）

```css
--gradient-core:linear-gradient(100deg,#E4572E 0%,#E4A02B 100%);
--gradient-core-3:linear-gradient(100deg,#E4572E 0%,#E4572E 42%,#E4A02B 100%);
```

使用箇所は、背景グロー、縒り線・区切り、プライマリCTAの縁、キーワードの下線、番号・ドットに限定します。グラデーション文字と、大きな面のベタ塗りには使いません。

### State Colors

状態は「色＋アイコン＋ラベル」で必ず併用する（色のみに依存しない）。ブランド朱赤と混同しない色を選ぶ。

| Token | HEX | 用途 |
|---|---|---|
| `--color-error` | `#A01B12` | エラー。朱赤より深く青みのある赤。必ず ⚠ アイコン＋テキスト併用 |
| `--color-success` | `#3E6B4E` | 成功。彩度を抑えたセージ。✓ アイコン＋テキスト併用 |
| `--color-warning` | `#B8791F` | 注意。山吹を一段沈めた色。⚠ アイコン＋テキスト併用 |
| `--color-focus` | `#E4A02B` | フォーカスリング |

### Contrast（算出値・実装時にツール再検証）

| 前景 / 背景 | 比率 | 判定 |
|---|---|---|
| `--color-text` #F7F1E7 / `--color-bg` #120F0A | ≈ 17.0:1 | AAA |
| `--color-text-soft` #BDB4A6 / `--color-bg` | ≈ 9.3:1 | AAA |
| `--color-yellow` #E4A02B / `--color-bg` | ≈ 8.5:1 | AAA（アクセント専用） |
| `--color-red` #E4572E / `--color-bg` | ≈ 5.2:1 | AA |

※上記は算出値。実装時に自動ツール（axe / WebAIM 等）で最終検証する。

### Accessibility Rules

- 本文と背景には十分なコントラストを確保する
- 色だけで状態や意味を伝えない
- 朱赤と山吹色を本文色として多用しない
- アクセント色は、重要度と機能に応じて限定的に使う
- ホバー、選択、エラー、成功は形、ラベル、アイコンも併用する

## 13. Typography

### Font Families (Confirmed)

> **📌 2026-07-26 決定：全面ゴシック。** 事業方向の転換（越境・挑戦・まずやってみる）に伴い、
> 見出しの明朝運用を取りやめ、**見出し・本文ともゴシック**に統一する。
> 対比は「書体の種類」ではなく **ウェイト・サイズ・余白**でつくる。
> 理由：明朝は「静かな和の落ち着き」に寄りすぎ、B2Bでの実務的な信頼感・現代性と合わないため。
> 世界観の"人らしさ"は**曲線モチーフ**が担い、書体は可読性と明快さに徹する。

すべて Google Fonts 系で無償・Web 埋め込み可能なものを基準にする。

| Role | Family | Fallback |
|---|---|---|
| Heading / Display | **Zen Kaku Gothic New**（Bold 700 / Medium 500） | `"Noto Sans JP","Hiragino Kaku Gothic ProN","Yu Gothic",sans-serif` |
| Body | **IBM Plex Sans JP**（Regular 400 / Medium 500） | `"Noto Sans JP","Hiragino Kaku Gothic ProN","Yu Gothic",sans-serif` |
| Latin / 数字 | IBM Plex Sans | `system-ui` |

- ロゴのワードマークは専用ロゴデータを使用し、本文フォントで代替しない。
- **丸ゴシックは使わない**（幼く見えるため。§8「やさしいが、幼くない」）。
- 明朝は原則使用しない。使う場合は引用など**ごく限定的な用途**に留め、事前に判断すること。

### Type Scale（base 16px / rem）

日本語本文は行間 1.7 を基準にゆとりを持たせる。

| Token | 用途 | size | line-height | weight | letter-spacing |
|---|---|---|---|---|---|
| `--fs-display` | ページ主見出し | 2.5rem (40px) | 1.3 | **700** | 0.06em |
| `--fs-h1` | H1 | 2rem (32px) | 1.35 | **700** | 0.06em |
| `--fs-h2` | H2 | 1.5rem (24px) | 1.4 | **700** | 0.05em |
| `--fs-h3` | H3 | 1.25rem (20px) | 1.5 | **600** | 0.04em |
| `--fs-body-lg` | リード文 | 1.125rem (18px) | 1.8 | 400 | 0.01em |
| `--fs-body` | 本文 | 1rem (16px) | 1.7 | 400 | 0.01em |
| `--fs-sm` | 補助 | 0.875rem (14px) | 1.6 | 400 | 0.02em |
| `--fs-caption` | キャプション（最小） | 0.8125rem (13px) | 1.5 | 400 | 0.02em |

- 見出しは **Zen Kaku Gothic New**、本文は **IBM Plex Sans JP**。
- 13px を最小とし、これより小さい文字を本文・ラベルに使わない。
- **見出しと本文の差は「ウェイト（700/600 vs 400）＋サイズ＋余白」でつける。** 書体を変えない。
- 見出しの字間は `0.06em` を基準に開け、余白と「急かさない」人格を表す。

### Typography Rules

- 丸ゴシックを過剰使用しない
- 小さすぎる文字を避ける
- 細すぎるウェイトを本文に使用しない
- 低コントラストのグレー文字を避ける
- 行間と段落間に十分な余白を設ける
- 日本語の文字量を前提に設計する
- 英語を装飾として過剰使用しない
- Light ウェイトを本文・見出しに使わない（細すぎ回避）
- 書体を混ぜて対比をつくらない（**ウェイトと余白**で階層を出す）

## 14. Photography and Material Direction

### Photography Principles

理想化された「幸せな生活」や、ストックフォト的な笑顔の乱用を避けます。

生活や仕事の途中にある、自然な瞬間を扱います。

- 本や資料を読む
- ノートに書く
- 対話する
- ひとりで考える
- オンラインでつながる
- チームで準備する
- 複数人が同じ場所で、それぞれ異なることをしている
- プロジェクトの場や手元
- 小さな行動を始める瞬間

### String / Mizuhiki-inspired Material

ロゴの紐モチーフは、実写の中で「意味を持った静かな記号」として使用します。

#### Possible Expressions

- ノート、本、カード、名刺などのそばに細い紐を添える
- 複数の紐が緩やかに交差する
- 人の手元と紐を組み合わせる
- 机上の複数要素を紐がつなぐ
- 紐をしおりやカードの留め具として使う
- UIの視線誘導ラインと、写真内の紐の流れを呼応させる
- 空間の一部に細い線状のインスタレーションを置く

#### Usage Principles

- 紐を主役にしすぎない
- ロゴの装飾的コピーではなく、思想を実写へ翻訳する
- 和風や伝統文化の印象に固定しない
- 紐の意味が説明なしでも自然に受け取れる構成にする
- 情報の読みやすさと視線誘導を優先する

#### Avoid

- ご祝儀袋、婚礼、贈答品に見える表現
- 神社仏閣、宗教、占いを想起させる演出
- 伝統工芸ブランドに寄りすぎる表現
- 和柄や和装小物の多用
- 紐を大量に配置し、画面を複雑にする
- 結び目に過剰な象徴性を持たせる
- 装飾が情報より強くなる構成

## 15. Iconography and Graphic Motifs

### Icon Principles

- 線を基調とする
- 角を丸くしすぎない
- 親しみと明瞭さのバランスを取る
- 装飾目的より、意味の理解を優先する
- アイコン単体に依存せず、必要に応じてラベルを併記する

### Graphic Motifs

- 二本以上の線が交差する
- 線の太さや密度が変化する
- 円や弧が重なる
- 異なる点の間に接点ができる
- 一部がほどけ、余白をつくる
- 点と線で関係性を可視化する
- 人とプロジェクトの情報が近づく様子を抽象化する

## 16. UI Foundations

### General UI Principles

- 初見でサービス内容が分かる
- 目的別に入口を整理する
- 選択肢を一画面に増やしすぎない
- リンク先の内容が予測できる
- カードを乱用せず、文章として読める構成を残す
- CTAは主画面内で最大2つ程度に抑える
- 重要度の差を色だけで表現しない
- スマートフォンで片手操作しやすくする
- 安心して離脱できる
- 外部リンクであることが分かる
- AIの推薦理由を確認できる

### Buttons

#### Primary

最も重要な行動にのみ使用する。

Examples:

- 相性を確認する
- プロジェクトを見る
- マッチングを始める

#### Secondary

情報理解や比較のための行動に使用する。

Examples:

- 仕組みを知る
- 詳細を見る
- 条件を確認する

#### Tertiary / Text Link

心理的負担の低い行動に使用する。

Examples:

- あとで見る
- 今は決めない
- 相談してから考える
- 推薦理由を見る

### Match Result UI

AIマッチング結果では、単一スコアだけを強調しません。

表示すべき情報：

- 相性の概要
- 推薦理由
- 活かせる経験や強み
- 合致している条件
- 確認が必要な条件
- 不足している情報
- 本人が変更できる条件
- 次の選択肢

### Match Score Rules

- 点数を人の価値として見せない
- 順位だけで判断させない
- 数値の根拠を表示する
- 「不一致」を否定的に断定しない
- データ不足と相性の低さを区別する
- AIの確信度や不確実性を必要に応じて示す

## 18. HCD and Accessibility Principles

### Comprehension

- 初めて訪れた人が5秒程度でサービスの概要を理解できる
- 「誰と誰をつなぐサービスか」が分かる
- AIが何を分析し、何を提案するかが分かる
- AIと人の役割分担が分かる

### Autonomy

- AIの推薦を断る、保留する、再検討する選択肢を用意する
- 本人の意思を優先する
- 推薦結果を決定事項として見せない
- 「今は決めない」という選択を尊重する

### Transparency

- 推薦理由を説明する
- 使用する情報の種類を示す
- データ不足や不確実性を隠さない
- AIによる分析であることを明示する
- 人が介在する場面を明確にする

### Accessibility

- 十分な文字サイズと行間を確保する
- 背景と文字のコントラストを確保する
- キーボード操作を想定する
- フォーカス状態を明確にする
- スクリーンリーダーで理解できるラベルを付ける
- 画像に代替テキストを設定する
- タップ領域を十分に確保する
- 動きを停止できるようにする
- 色だけで意味を伝えない
- 自動再生や強い点滅を避ける

### Psychological Safety

- 不採用や不一致を人格評価として表現しない
- 不安を過度に刺激しない
- 人材を市場価値だけで表現しない
- 強い自己改善や成長を押しつけない
- 利用者が自分のペースで進めるようにする

---

## 19. Do / Don't

### Do

- AIを、理解と選択を支援する手段として見せる
- 人とプロジェクト双方の視点を扱う
- 推薦理由を分かりやすく説明する
- 余白を活かし、静かな信頼感をつくる
- ロゴの紐を、関係性を表す視覚言語へ展開する
- 多様な働き方や価値観を尊重する
- 具体的な活動や利用方法を示す
- 情報設計をビジュアルより優先する

### Don't

- AIを万能な判定者として見せる
- 「最適」を絶対的な正解として断定する
- 人を点数だけで比較する
- スピリチュアルや自己啓発に寄りすぎる
- ウェルビーイングを理想化された生活写真だけで表す
- 水引モチーフを婚礼や和風の装飾として乱用する
- 抽象的な理念だけでサービス内容を曖昧にする
- CTAやアニメーションで行動を急かす
- 低コントラスト、小さな文字、細すぎる文字を使う

## 25. Component Specifications

トークン参照で最小仕様を定義する（§16 の思想を実装値に落としたもの）。共通: タップ領域 min 44×44px、フォーカスは `--color-focus` の 2px outline + 2px offset。

### Button / Primary
- 黒地 `#0E0C0A`、文字 `--color-white`（weight 600）、外周に `--gradient-core`
- padding `12px 20px`、radius `--radius`、min-height 44px
- 最重要アクション 1〜2 個まで（§16）。例:「相性を確認する」

- hover はオレンジの外グローを少し強めます。グラデーションを面には敷きません。

### Button / Secondary
- bg `--color-surface`、文字 `--color-text`、border 1px `--color-border`
- hover: bg `--color-surface-2`

### Button / Tertiary・Text link
- 文字 `--color-text`、hover で `--color-red` ＋ underline
- 心理的負担の低い行動（「あとで見る」「今は決めない」）

### Link Row（名刺ハブの主要素）
- 構成: `[アイコン] ラベル … [外部リンクのシェブロン]`
- 面 `--color-surface`、radius `--radius`、padding `--space-4`
- 外部リンクは視覚的に明示（シェブロン / ↗）＋ `rel="noopener"`

### Card
- 面 `--color-surface`、`backdrop-filter:blur(22px)`、border 1px `--color-border`、radius `--radius`、shadow `--shadow`、padding `--space-5`

### Input / Form
- 面 `--color-white`、border 1px `--color-border`、radius `--radius-sm`、padding `12px`
- focus: border `--color-focus` ＋ ring。エラー時は border `--color-error` ＋ アイコン ＋ 説明文
- ラベルは常時表示（プレースホルダのみに頼らない）

### Divider / 縒り線モチーフ
- セクション区切りに、朱赤 × 山吹の縒り紐 SVG を細く低彩度で使用（hub-site の `.twist` を踏襲）
- 主役にしない・多用しない（§14）

## 26. Pattern & Motif Library

ブランドガイドの4文様は、Dark Glass の主表現と競合しない補助素材として定義する。

| 文様 | 読み | 意味 | UI での用途 |
|---|---|---|---|
| 立涌文様 | たてわく | 立ちのぼる気運・発展 | ヒーローやセクション帯の地紋 |
| 七宝繋ぎ | しっぽうつなぎ | 円＝縁が繋がる・調和 | 「つながり」を語る面の地紋 |
| 網代 | あじろ | 編み・強度・関係性 | フッター／区切りの地紋 |
| 檜垣文様 | ひがき | 守り・厄除け | カバー画像のプレースホルダ等 |

### Usage Rules
- 近黒上に白または山吹を極低コントラストで重ね、opacity は目安 2–5%。
- 背景グローと同じ領域には置かず、光と文様を競合させない。
- 本文テキストの直下には敷かない（可読性優先）。
- 一画面で使う文様は基本 1 種類。複数を混在させない。
- §14 の禁止（婚礼・宗教・和風に寄りすぎ）を必ず参照。柄を「装飾の主役」にしない。
